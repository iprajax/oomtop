# Linux fixtures

Replayed through `oomtop_collect::linux::decode_full` / `replay_full` on any OS (SPEC §6.1, §17) — no Linux box,
GPU or root needed in CI.

| Fixture | What it is |
|---|---|
| `tree-amd/` | A fake filesystem root (`proc/`, `sys/`, `etc/`, `usr/`) read by the **real Sources** in tests. Fedora laptop: Ryzen 7 7840HS (16 cpus, amd-pstate at 1.4 of 5.1 GHz), Radeon 780M APU (`card0`, `gpu_metrics` v2.2) + RX 7700S dGPU (`card1`, `gpu_metrics` v1.3), llama-server holding 7.5 GiB VRAM (drm fdinfo, dup'd fd), systemd-oomd with Fedora drop-ins + a local `SwapUsedLimit=80%`, a 12 GiB `memory.max` on `user@1000.service`, battery discharging at 41 %, `platform_profile=low-power`, acpitz over its passive trip, RAPL `energy_uj` root-only, a Claude Code session whose environ holds a token that must never leak. `links.txt` lists the symlinks (`exe`, `cwd`, `fd/*`) and permissions git cannot carry; tests apply them to a temp copy. |
| `nvidia-oom-trend.json` | Replay frames (`{meta, frames: [[RawSample…]]}`) of an Ubuntu workstation: 64 GiB, RTX 4090 via NVML, `earlyoom -m 5 -s 10`. A python job leaks ~1.5 GiB / 10 s: MemAvailable 30 → 3 GiB, swap filling, PSI rising, then a kernel OOM kill (`vmstat oom_kill +1`, `@oom/kills` names the victim) and recovery. smaps_rollup is read on even frames and cached on odd ones (estimate path). |

The `gpu_metrics` blobs follow the struct layouts of upstream `kgd_pp_interface.h` (offsets checked with
`offsetof`, 2026-09): v1.1–1.3 temperatures at byte 4, v2.1+ APU layout with the timestamp after the activity
fields (`temperature_gfx` @4, `average_gfx_activity` @28 in centi-%, `average_socket_power` @40 in mW).

Both are **synthetic** (formats per the kernel docs: `proc(5)`, `cgroup-v2.rst`, `drm-usage-stats.rst`,
`sysfs-api.rst`, `hwmon/sysfs-interface.rst`, `kgd_pp_interface.h`), generated by
`uv run fixtures/linux/gen_fixtures.py`. Real captures go next to them (see Capture below).

## RawSample format (`payload.type = "linux_files"`, `LinuxFilesRaw`)

```json
{ "type": "linux_files",
  "files":   { "meminfo": "MemTotal: …", "1234/stat": "1234 (comm) S …", "1234/exe": "/usr/bin/x",
               "/sys/fs/cgroup/user.slice/memory.max": "max\n",
               "/sys/class/drm/card0/device/gpu_metrics": "hex:8000010300…",
               "/sys/class/drm/card0/device/hwmon/": "hwmon3\n",
               "@nvml": "driver: 550.107.02\ndevice 0\nname: …", "1234/@smaps_cache": "Pss: … kB\nRss: … kB\nAgeMs: …" },
  "missing": { "/sys/class/powercap/intel-rapl:0/energy_uj": "permission denied" },
  "markers": { "1234": { "session_id": "3f2a…", "agent": "claude-code", "keys": ["CLAUDECODE"] } },
  "clk_tck": 100, "page_size": 4096, "truncated": false }
```

Key conventions:

- **`/proc`-relative** (`meminfo`, `vmstat`, `stat`, `loadavg`, `pressure/{memory,cpu,io}`, `self/cgroup`,
  `sys/kernel/*`, `driver/nvidia/version`, `<pid>/{stat,statm,status,cmdline,cgroup,oom_score,io,smaps_rollup}`,
  `<pid>/fdinfo/<fd>`; `exe`/`cwd` hold the `readlink` target).
- **Absolute** for everything outside `/proc` (`/sys/…`, `/etc/systemd/…`, `/usr/lib/systemd/…`,
  `/etc/default/earlyoom`). Binary files are `hex:`-encoded; a key ending in `/` is a directory listing.
- **Synthetic `@…` records** written by the Sources, never file contents: `@nvml` (device table),
  `@nvml/procs` (`gpu pid bytes`), `@status/<sub-source>` (`unavailable: …`), `@oom/scan` (top `oom_score`
  candidates: `pid starttime score comm`), `@oom/daemons` (`comm pid`), `@oom/kills` (`at_ms pid name source`),
  `@users` (`uid name`, only uids seen), `@gpu/devices` (`drm N`, `nvidia 0|1`, `card <pci> <driver> <vram>`),
  `@drm/scanned` (`pid:starttime` whose fds were scanned), `<pid>/@smaps_cache`, `<pid>/@model_files`.

`environ` is never stored: the Source converts allowlisted keys to `markers` (values hashed) and drops every
other pair without copying it. `maps` is parsed in flight (only model-file paths are kept).

## Capture

`cargo run -p oomtop-collect --example capture -- fixtures/linux/<name>.json --frames 2` (same redaction as
macOS). Record thermal/battery state in `meta.notes`.
